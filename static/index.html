Detect with a specialist, explain with a generalist

        
Small fine-tuned code models are fast and measurable at spotting defects, but they only output a number. Large generative models explain well, but are slow and hard to evaluate. BugLens chains the two.

      

      
    
        
  1. 
          
    Tokenize
    
          
    The function is split into sub-word tokens with the model's own BPE tokenizer and cut to 400 tokens, the same length used by the CodeXGLUE baseline.
    
        
    2. 
        
  2. 
          
    Encode and classify
    
          
    CodeBERT (125M parameters, encoder) or the CodeT5-small encoder reads the tokens. A linear layer on top outputs one number, and sigmoid turns it into the probability of a defect.
    
        
    3. 
        
  3. 
          
    Decide
    
          
    Probability of 0.5 or more means buggy. The attention of the last layer shows which tokens the model looked at most.
    
        
    4. 
        
  4. 
          
    Explain and fix
    
          
    Flagged code goes to Gemini with the detector's score as a hint. Gemini returns structured JSON: bug type, severity, line numbers, explanation and a corrected version.
    
        
    5. 
      

      

        

          
Dataset

          
CodeXGLUE Defect Detection (Devign): 27,318 real C functions from FFmpeg and QEMU, labelled vulnerable or clean by security experts.

          

            
Train21,854

            
Validation2,732

Training

          

            
LossBinary cross-entropy (with logits)

            
OptimizerAdamW, weight decay 0.01

            
ScheduleCosine with 10% warmup

            
StoppingBest validation accuracy, patience 2

            
HardwareGoogle Colab T4 GPU

          

        

        

          
Cross-language probe

          
The model only ever sees C during training. To test transfer, 18 hand-written bug and fix pairs (13 Python, 5 C) are scored after training. The same pairs fill the specimen drawer.
